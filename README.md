# CBF & CMRO₂ Viewer

A web page for the Akbari lab pipeline. Drag MATLAB `.mat` files onto it and get
blood-flow and oxygen-metabolism results, charts and a CSV — from any computer,
with nothing to install.

**Your data never leaves your machine.** The page is static; all the maths runs
in your browser. There is no server and no upload.

---

## Deploy it (GitHub Pages)

1. Create a repository and copy everything in this folder into it.
2. Push.
3. Settings → Pages → Source: **Deploy from a branch**, branch `main`, folder `/ (root)`.
4. It goes live at `https://<user>.github.io/<repo>/` in a minute or two.

No build step. No dependencies to install. It is plain HTML, CSS and JavaScript
with two libraries already vendored in `vendor/`.

> **Before you publish:** a public repository makes every file in it public.
> The sample `.mat` files and test fixtures shipped here are **synthetic** — no
> animal data — so this folder is safe to publish as-is. If you later swap in
> real recordings for testing, either keep the repo private or delete them from
> `test/matfiles/` and `fixtures/` first.

## Using it

Drop in one or both file types per animal:

| File | What it must contain | Gives you |
|---|---|---|
| **LSI** (required) | `time` and `mean_data` | blood flow: rCBF, cleaned traces |
| **SFDI ROI** (optional) | `MetabolismTime`, `hbo2`, `hbr`, `hbtot`, `scatter730` | adds oxygen: aCMRO₂, rCMRO₂, rCBF/rCMRO₂ |

Drop many animals at once — files are grouped by the animal name in the
filename (`Mouse 272_Baseline.mat` → `Mouse272`). **If an animal has no SFDI
file it still works**, you just get flow results and a note saying oxygen was
skipped.

Reads MATLAB **v6, v7 and v7.3** files, including variables nested inside structs.

### Settings

| Setting | Meaning |
|---|---|
| Baseline anchor | Relative values are measured against the half-minute before this time. `1` for a plain baseline recording; the intervention onset otherwise. |
| Artifact thresholds | Flow outside this range is treated as noise and replaced with the last good sample. |
| Camera exposure | Must match acquisition — it scales the flow values. |

## Is it giving the right answers?

Open **`test.html`**. It runs 22 checks comparing this browser's output against
reference values generated by the lab's MATLAB pipeline, and prints a pass/fail
for each.

The result on a modern browser:

| Quantity | Agreement with MATLAB |
|---|---|
| D_b (blood-flow coefficient) | **exact** — every one of the values identical |
| Cubic spline resampling | ~1e-15 |
| Absolute CMRO₂ | ~1e-17 |
| Relative CBF and CMRO₂ | ~5e-13 |

D_b has to match exactly because it is picked from a discrete grid — a single
differing value would mean the fit landed on a different grid point. The
continuous quantities differ only in the last few bits, which is unavoidable
when arithmetic runs on a different platform.

The most likely way a port like this silently goes wrong is the spline:
MATLAB uses the **not-a-knot** end condition, and most quick JavaScript
implementations use a natural spline instead, which shifts every interpolated
value. `js/spline.js` implements not-a-knot and `test.html` checks it.

## What's in here

```
index.html          the app
test.html           verification against MATLAB — open this to check the build
js/
  spline.js         not-a-knot cubic spline (matches MATLAB's spline())
  pipeline.js       the CMRO2 maths, ported from the verified MATLAB code
  matfile.js        .mat reader for v6/v7 (zlib) and v7.3 (HDF5)
  analysis.js       file sniffing, animal pairing, batch running
  charts.js         line charts
  app.js            UI
fixtures/           MATLAB reference values used by test.html  (synthetic data)
test/matfiles/      sample .mat files in each format            (synthetic data)
test/*.mjs          the same checks runnable under Node
vendor/
  h5wasm/           HDF5 reader (wasm embedded, no separate fetch)
  uplot/            charting
```

### Running the tests outside a browser

```bash
npm install          # only needed for the Node test runner
node test/test_spline.mjs
node test/test_pipeline.mjs
node test/test_matfile.mjs
```

### Regenerating the reference fixtures

If the MATLAB pipeline changes, regenerate `fixtures/*.json` from MATLAB and
re-run the tests. The generating code is in the project notes; the fixtures are
plain JSON holding the inputs and MATLAB's outputs for the same run.

## Limits

- **This is a third implementation** of the maths (original scripts → refactored
  MATLAB → this). It is verified, but verification is only as current as the
  fixtures. Re-run `test.html` after any change to either side.
- Raw image processing is **not** here. Turning `.tif` frames into `time` /
  `mean_data`, and SFDI frames into haemoglobin maps, still happens in MATLAB —
  those stages need the Monte Carlo model and phantom calibration data.
- `K = 1/(0.01·SFI)`, the SFI-to-speckle-contrast conversion, is carried over
  from the original code unchanged. It is not dimensionally consistent with
  `SFI = 1/(2·T·K²)`; relative results are unaffected, but verify it before
  publishing absolute D_b or CMRO₂ values.
